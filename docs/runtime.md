# Таймеры, cvar'ы, звук

## Таймеры

```lua
local id = after(3, function() ... end)     -- один раз через 3 сек
local tick = every(1, function() ... end)   -- каждую секунду
cancel(id)                                  -- вернёт true, если нашёлся
```

Идут по времени сервера, тикают в `StartFrame`. Переживают смену карты: время
на новой карте начинается с нуля, и модуль переносит на него все отложенные
сроки — `after(600, ...)` останется «через десять минут от момента постановки».

Ошибка в разовом таймере логируется. Повторяющийся после ошибки снимается —
иначе он завалил бы лог трейсбеком каждый кадр.

Таймеры принадлежат создавшему их плагину и умирают вместе с ним при `lua_reload`.

**Слот за время ожидания может занять другой игрок.** Если это важно, проверяй
не только `p:connected()`, но и ник или steamid:

```lua
after(3, function()
	if p:connected() then p:hud("Welcome") end
end)
```

## Cvar'ы

`cvar(name)` даёт объект существующей переменной (или `nil`), `cvar_register`
заводит свою.

```lua
local ft = cvar("mp_freezetime")
print(ft:int(), ft:float(), ft:str())
cvar("mp_friendlyfire"):set(1)

local enabled = cvar_register("greet_enabled", "1", { archive = true })
if enabled:int() ~= 0 then ... end
```

| метод | описание |
|-------|----------|
| `c:int()` | значение как целое |
| `c:float()` | как число |
| `c:str()` | как строка |
| `c:set(v)` | записать (число или строку) |
| `c:name()` | имя переменной |

Флаги в `cvar_register`: `archive` (сохраняется в конфиг), `server` (уведомлять
игроков об изменении), `protected` (не отдавать значение клиентам — для паролей).
Второй аргумент — значение по умолчанию, строкой.

Cvar'ы живут в движке вечно: повторный `cvar_register` того же имени вернёт
объект, не сбрасывая значение, поэтому `lua_reload` их не трогает.

## Звук и прекеш

Движок принимает прекеш только в момент загрузки карты. Угадывать этот момент из
скрипта неудобно, поэтому `precache_sound` просто запоминает ресурс, а модуль
сам проигрывает список на каждой карте:

```lua
precache_sound("items/9mmclip1.wav")   -- один раз, при загрузке плагина
precache_model("models/w_backpack.mdl")

p:play_sound("items/9mmclip1.wav", { attenuation = 0 })
all:play_sound("items/9mmclip1.wav")
```

| поле `opts` | по умолчанию | что делает |
|-------------|--------------|------------|
| `volume` | `1.0` | громкость 0..1 |
| `attenuation` | `0.8` | затухание с расстоянием; `0` — одинаково слышно везде, для интерфейсных звуков |
| `channel` | `0` | канал звука |
| `pitch` | `100` | тон: больше — выше, меньше — ниже |

`precache_sound`, вызванный когда карта уже загружена (например `lua_reload`
посреди игры), запомнит ресурс и введёт его в игру со следующей карты. В консоль
об этом идёт строка.

### Лимит в 512 слотов

У GoldSrc жёсткий предел: 512 слотов на звуки и 512 на модели. Переполнение не
возвращает ошибку — движок падает с `Host_Error`, и сервер умирает.

Модуль следит за занятостью и отказывает **до** переполнения: ресурс не
прекешится, плагин-виновник отключается (хендлеры и таймеры снимаются, в
`lua_list` он помечен `[FAILED]`), сервер продолжает работать. В консоли будет,
какой плагин и на каком ресурсе упёрся.

Запас смотреть через `lua_precache`:

```
precache sounds: 12/512 used, 500 free (1 registered by plugins)
precache models: 0/512 used, 512 free (0 registered by plugins)
```

Точность зависит от движка:

| | |
|---|---|
| **с ReHLDS API** | перехватываются все прекеши сервера — цифры точные |
| **без него** | видно только свои — это нижняя граница, `lua_precache` об этом пишет |

Проверка версии ReHLDS строгая намеренно: нужные хуки лежат в конце vtable
интерфейса, и обращение к ним при несовпадении версий уронило бы сервер — ровно
то, от чего этот механизм защищает.
