# Установка

Работает как обычный metamod-модуль. Три шага — и первый плагин уже
отвечает игроку в чате.

## 1. Поставь бинарник

Скачай `lua_mm.dll` (Windows) или `lua_mm_i386.so` (Linux) из
[релизов](https://github.com/KotyaraKryt/cs-lua/releases) и положи вместе с
папками `core/` и `include/` в `cstrike/addons/lua/`. Собрать самому из
исходников можно — [Сборка модуля](building.md).

Нужен [metamod-r](https://github.com/rehlds/Metamod-R) и
[ReGameDLL_CS](https://github.com/s1lentq/ReGameDLL_CS): без ReGameDLL
модуль загрузится, но раунды, деньги и команды игроков работать не будут.
[ReHLDS](https://github.com/dreamstalker/rehlds) не обязателен, но даёт
точный учёт прекеша.

## 2. Впиши строку в plugins.ini

В `cstrike/addons/metamod/plugins.ini`:

```ini
win32 addons/lua/lua_mm.dll
linux addons/lua/lua_mm_i386.so
```

Рестартуй сервер. Модуль грузится один раз и не выгружается на лету —
`meta unload` запрещён, дальше только `lua_reload`.

## 3. Проверь

`lua_list` в консоли — если список появился (пока пустой), модуль
загрузился. Пустой он и тогда, когда все плагины упали при старте —
причина печатается в консоль рядом с именем файла.

## Первый плагин

Плагин — папка, не одиночный файл (подробности — [Структура плагина](plugins.md)):

`cstrike/addons/lua/plugins/hello/manifest.lua`:

```lua
plugin { name = "Hello", api_version = 1 }
```

`cstrike/addons/lua/plugins/hello/init.lua`:

```lua
hook.add("player_spawn", "hello.greet", function(e)
	e.player:chat("{green}Привет, {default}" .. e.player:name())
end)
```

`lua_reload` — и при следующем спавне игрок видит сообщение. `lua_list`
покажет `hello` без `[FAILED]`. Дальше — [Структура плагина](plugins.md).

## Раскладка файлов

```
cstrike/addons/lua/lua_mm.dll         (Windows) или lua_mm_i386.so (Linux)
cstrike/addons/lua/core/              базовый слой, едет вместе с модулем
cstrike/addons/lua/include/           библиотеки для require
cstrike/addons/lua/data/              groups.lua, users.lua
cstrike/addons/lua/plugins/           плагины
```

| каталог | кому принадлежит |
|---|---|
| `core/`, `include/` | модулю: обновляй вместе с бинарником, версии должны совпадать |
| `data/`, `plugins/` | серверу: обновление их не трогает |

Стартовые `groups.lua` и `users.lua` лежат в репозитории в `scripts/data/`.
Скопируй один раз вручную.

## Консольные команды

| команда | что показывает |
|---|---|
| `lua_list` | загруженные плагины; `[FAILED]` у упавших |
| `lua_precache` | занятые слоты прекеша |
| `lua_reload` | перечитывает `core/`, `include/`, `plugins/` |

## Права плагинов

Плагин выполняется с правами серверного процесса: `luaL_openlibs` открывает
в том числе `ffi`, поэтому доступны память процесса, файловая система и
системные вызовы. По правам это модуль AMXX (`.dll`/`.so`), а не
`.amxx`-плагин.

Игрок загрузить или выполнить Lua-код не может: ник, текст в чате и
аргументы команды попадают в плагин как данные.

<Warning>
Доступ к `plugins/` равен доступу к серверу. Lua не компилируется — код лежит
рядом текстом, читай его перед установкой.
</Warning>

## Что изоляция не даёт

У каждого плагина своя таблица глобальных переменных и свой кеш `require`, и
модуль умеет снять один плагин, не трогая остальные. Это разделение имён —
чтобы два плагина не мешали друг другу случайно. Песочницей это не является:
разница видна не на злом коде, а на обычной ошибке.

| ошибка в плагине | что происходит |
|---|---|
| вечный цикл | сервер перестаёт отвечать; помогает только перезапуск процесса |
| утечка памяти | LuaJIT на x86 упирается в свой лимит, дальше падение |
| ошибка в `ffi` | segfault всего процесса, без Lua-трейсбека |
| `sv.cmd("quit")` | сервер выключается |
| чтение чужого `data/` | ничего не мешает: каталоги разделены по имени, не по правам |

Ограничения по времени и по памяти на обработчик нет. Сторож есть ровно один —
на [запросы к базе](api/db/index.md#запросы-идут-в-кадре): SQLite умеет
прерывать своё выполнение, произвольный Lua-код прервать так же нельзя, не
оставив его на середине записи в файл.

Плагин из непроверенного источника читай перед установкой — код лежит рядом
текстом. Свой собственный плагин при этом ничем не безопаснее чужого: цикл
без выхода вешает сервер одинаково.

Что помогает на практике:

- `lua_reload <plugin>` вместо полной перезагрузки — ошибка в одном плагине
  не требует поднимать состояние целиком;
- [`lua_profile`](api/console.md#профилировка) показывает, чей обработчик
  ест кадр, до того как это станет заметно игрокам;
- повторяющиеся ошибки в логе троттлятся, поэтому упавший обработчик не
  забьёт диск за ночь.

Вход по нику (`["name:Вася"]` в `users.lua`) годится только для LAN: ник
подделывается, пароль передаётся открытым текстом. На публичном сервере
права выдавай по SteamID — [access](api/access/index.md).
