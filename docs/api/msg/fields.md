# Поля сообщения

Каждая функция описывает одно поле в порядке провода — сама ничего не
отправляет, только проверяет диапазон и возвращает значение, которое
[`msg.send`](send.md) пишет по очереди.

```lua
msg.send("one", "TextMsg", e.player,
  msg.byte(4), msg.string("hello"))
```

| Функция              | Диапазон / ограничение         | Соответствует SDK |
| --------------------- | -------------------------------- | ------------------ |
| `msg.byte(n)`          | `0..255`                          | `WRITE_BYTE`        |
| `msg.char(n)`          | `-128..127`                       | `WRITE_CHAR`        |
| `msg.short(n)`         | `-32768..32767`                   | `WRITE_SHORT`       |
| `msg.long(n)`          | любое 32-битное целое             | `WRITE_LONG`        |
| `msg.angle(f)`         | число, градусы                    | `WRITE_ANGLE`       |
| `msg.coord(f)`         | число, игровые единицы            | `WRITE_COORD`       |
| `msg.string(s)`        | до 191 байта                      | `WRITE_STRING`      |
| `msg.entity(v)`        | игрок или объект `ents`, индекс `>= 1` | `WRITE_ENTITY` |

### Возвращает

Каждая функция возвращает одно значение — его нужно передать в `msg.send`
как есть, не хранить и не пересобирать руками.

<Warning>
Значение вне диапазона — ошибка Lua сразу в момент вызова `msg.byte`/
`msg.short`/..., до `msg.send`. Так проще найти, какое именно поле не влезло.
</Warning>

`msg.string` проходит через ту же кодировку, что и `p:hud()`/`p:say()`:
`cslua_cp1251` переключает UTF-8 → CP1251 для старых клиентов, по умолчанию
выключено.

`msg.entity` принимает и игрока (`e.player`), и сущность из `ents` — что
угодно с полем `id` (игрок) или `index` (сущность). `0` (мир) не годится.
