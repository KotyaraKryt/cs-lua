# Объект игрока

```lua
p:health(p:health() + 25)
p:money(p:money() + 1000, true)
p:chat("{green}[Server]{default} привет")
```

`p` в хендлерах — объект слота. Объекты создаются один раз при старте и
переиспользуются: событие не аллоцирует память. Объект хранит только `p.id`,
все методы читают живое состояние.

Один метод делает обе работы: без аргумента читает, с аргументом пишет.

Получить объект вне хендлера:

| | |
|---|---|
| `player(id)` | по слоту, `nil` если пусто |
| `players()` | массив всех подключённых |
| `players{ alive = true, team = "CT" }` | с фильтром (нужен ReGameDLL) |
| `find_player(token)` | по слоту, `#userid` или части ника |
| `all` | глобальный объект: `all:chat(...)` шлёт всем |

`find_player` возвращает `nil, причина`, если игрок не найден или ник
неоднозначен.

## Кто это

| метод | описание |
|-------|----------|
| `p:name()` | ник |
| `p:ip()` | адрес вида `1.2.3.4:27005` |
| `p:steamid()` | authid (`STEAM_0:...`, `HLTV`, `STEAM_ID_LAN`) |
| `p:userid()` | userid движка, `-1` если игрока нет |
| `p:info(key)` | ключ из инфобуфера клиента (`p:info("_pw")`) |
| `p:connected()` | занят ли слот |
| `p:is_bot()` | серверный бот (`FL_FAKECLIENT`) |
| `p:is_hltv()` | HLTV-прокси (`FL_PROXY`) |

## Состояние

Читается и пишется напрямую в `entvars_t` через edict — без оффсетов и сигнатур,
работает на любом игровом модуле.

| метод | тип | описание |
|-------|-----|----------|
| `p:health([v])` | число | здоровье |
| `p:armor([v])` | число | броня |
| `p:frags([v])` | число | фраги |
| `p:gravity([v])` | число | множитель гравитации, 1.0 обычная |
| `p:maxspeed([v])` | число | максимальная скорость |
| `p:origin([x,y,z])` | 3 числа | позиция; запись телепортирует |
| `p:angles([x,y,z])` | 3 числа | поворот модели |
| `p:velocity([x,y,z])` | 3 числа | скорость |
| `p:aim()` | 3 числа | куда смотрит; только чтение, ими владеет клиент |
| `p:alive()` | bool | жив |
| `p:on_ground()` | bool | стоит на земле |
| `p:ducking()` | bool | сидит |

**Обращение к состоянию отключённого игрока — ошибка, а не тихий ноль.** Если не
уверен, что слот занят (например, в таймере), проверяй `p:connected()`.

## CS-состояние

Нужен ReGameDLL: команда, деньги и смерти живут не в `entvars`, а в
`CBasePlayer`. На ванильном `mp.dll` эти методы бросают понятную ошибку, а не
возвращают мусор.

| метод | тип | описание |
|-------|-----|----------|
| `p:team([s])` | строка | `CT`/`T`/`SPEC`/`NONE` |
| `p:money([v[, flash]])` | число | деньги; `flash = true` мигнёт HUD |
| `p:deaths([v])` | число | смерти; запись обновляет таблицу |
| `p:give(name)` | — | выдать предмет (`"weapon_ak47"`), как подбор |
| `p:strip([suit])` | — | убрать оружие; `true` — вместе с костюмом |
| `p:weapon()` | строка | classname активного оружия или `nil` |

У смены команды два режима:

```lua
p:team("CT")           -- мягко: сменить сторону, игрок остаётся жив
p:team("T", true)      -- force: игрок умирает и заходит заново
```

Вход из спектатора всегда идёт как force — мягко посадить зрителя в раунд нельзя.

## Админские действия

| метод | описание |
|-------|----------|
| `p:kick([reason])` | отключить; причина покажется игроку в консоль |
| `p:ban(minutes[, reason])` | забанить, `0` — навсегда |
| `p:slay()` | убить, никому не засчитывая |
| `p:slap([dmg])` | шлепок: урон (по умолчанию 1) и толчок |

`kick` и `ban` идут через консольные команды движка — это единственный способ
отключить клиента, и бан попадает в тот же список, которым админ управляет
обычными средствами (`writeid` сохраняет его между рестартами).

`slay` убивает через `TakeDamage` от имени мира, поэтому игра доигрывает смерть
целиком: дроп оружия, сообщение, проверка конца раунда. Обнуление здоровья
ничего этого не делает.

## Свои методы

Объекты общие для всех плагинов и защищены от записи: своё состояние держи в
таблице плагина, а не в `p.foo`.

Добавить объекту метод можно через `player_method(name, fn)` — им пользуется
core-слой (`p:can()` и остальные). Занятое имя переопределить не даст.
